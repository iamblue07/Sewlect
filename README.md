# Sewlect

Backend for Sewlect, an AI-powered outfit discovery and virtual try-on app (Master's thesis project). It builds outfits from a real product catalog, matched to each user's profile and budget, and lets users try them on virtually. The Flutter frontend is not started yet.

## Features

- **Accounts and profiles:** registration and login with JWT, profile with measurements, style preferences and budget, and two body photos for try-on.
- **Personalized feed:** an infinite-scroll feed of outfit recommendations ranked for each user.
- **Prompt search:** describe an outfit in plain text and get a batch of matching outfits, either for yourself or for someone else.
- **Stylist chat:** an AI stylist asks clarifying questions, shows a summary of what it will search for, and runs the search once you confirm. Every message and reply is checked by a content-safety model.
- **Outfit editing:** swap, remove or add individual garments, with alternatives ranked by how well they fit the rest of the outfit.
- **Virtual try-on:** an image of the user wearing an outfit, generated by [FASHN AI](https://fashn.ai).
- **Likes, saves and shares:** shared links open without an account.

## Tech stack

- Java 25, Spring Boot 4.1, Maven (wrapper included)
- PostgreSQL 18 with `pgvector`, Flyway migrations
- Redis 8 for rate limiting, job coordination and caching (optional)
- Cloudflare R2 for user photos and try-on images
- [DeepInfra](https://deepinfra.com) for request-time AI: `gpt-oss-120b` (chat), `Qwen3-Embedding-4B` (embeddings), `Llama-Guard-4-12B` (content safety)
- Local [Ollama](https://ollama.com) for the one-time catalog enrichment and embedding jobs
- Docker and Docker Compose; GitHub Actions for CI
- JUnit 5, Mockito and Testcontainers for tests

## Getting started

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- API credentials for [Cloudflare R2](https://developers.cloudflare.com/r2/), [DeepInfra](https://deepinfra.com) and [FASHN AI](https://fashn.ai)
- JDK 25, only if you run the app outside Docker

### Run with Docker

1. Copy `.env.example` to `.env.local` and fill in the empty values. `JWT_SECRET` and `RATE_LIMIT_HASH_SECRET` must each be at least 32 characters.
2. Build and start Postgres, Redis and the app:
   ```bash
   docker compose --env-file .env.local up -d --build
   ```
3. Optionally, load the product catalog: download `catalog.dump` from the [`catalog-seed-v1` release](https://github.com/iamblue07/Sewlect/releases/tag/catalog-seed-v1) into a `seed/` folder at the project root, then run:
   ```bash
   docker compose --env-file .env.local --profile seed up seed
   ```
4. Check that it's running: `http://localhost:8080/actuator/health` should return `{"status":"UP"}`.
5. Stop everything. Data is kept in Docker volumes.
   ```bash
   docker compose --env-file .env.local down
   ```

### Run from the IDE

Start only the backing services:

```bash
docker compose --env-file .env.local up -d postgres redis
```

Then run `SewlectApplication`. It reads `.env.local` automatically.

### Tests

Docker must be running; Testcontainers starts its own Postgres and Redis.

```bash
./mvnw verify
```

## API

All endpoints are under `/api/v1` and need a Bearer token, except authentication and the public outfit view. With the app running, the full interactive reference is at `http://localhost:8080/swagger-ui.html`, and the OpenAPI spec is at `/v3/api-docs` for importing into Postman.

| Area | Base path |
|---|---|
| Authentication | `/auth` |
| Account, profile and photos | `/users/me` |
| Feed | `/feed` |
| Outfits, prompt search, editing, likes and saves | `/outfits` |
| Public outfit view | `/public/outfits` |
| Stylist chat | `/stylist/conversations` |
| Virtual try-on | `/tryon` |

Every response has an `X-Correlation-Id` header. Include it when reporting a problem; it matches the app's log lines.

## Project structure

Code is organized by feature under `src/main/java/com/sewlect`: `identity`, `catalog`, `outfit`, `feed`, `social`, `tryon`, `stylist`, with shared infrastructure in `common`. Database migrations are in `src/main/resources/db/migration`.

## CI

Every push to `master` and every pull request runs the full test suite on GitHub Actions. When it passes on `master`, a Docker image for `amd64` and `arm64` is published to `ghcr.io/iamblue07/sewlect`, tagged with the commit SHA and `latest`.
